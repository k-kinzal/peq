The GQL statements peq reads well enough to refuse by name.

peq answers questions about source code it has just read out of a directory. A statement that changes a graph, manages a session or declares a graph type would be describing a database that does not exist, so none of them is implemented — but there are two ways not to implement a statement, and only one of them is honest.

Saying "expected a clause" tells a reader their GQL is wrong, which it is not: they wrote a statement the standard defines and peq chose not to answer. Saying so by name, under the status GQL gives a query it will not run, tells them the true thing — and tells a program the true thing too, since the code says "the query was

  • at fault" rather than "the query could not be read".
